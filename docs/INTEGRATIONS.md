# Integrations

Statuses (as reported by `GET /api/v1/health/dependencies`): `NOT_CONFIGURED` (needs a key that is absent) · `IMPLEMENTED` (keyless, no live call yet this process) · `CONFIGURED` (key present, not yet called) · `VERIFIED` (last live call succeeded) · `DEGRADED` (last live call failed) · `DISABLED` (turned off by config). A key alone never produces `VERIFIED`.

## Place and weather calls (providers.ts)
- **Cache:** per process, keyed by the rounded (~1 km) cell plus what the source uses: Overpass by cell and radius, SerpApi by cell and normalized query (lowercased, ≤ 100 chars), Open-Meteo by cell. Entries live 10 min; past 500 entries the oldest is dropped (`RULES.providerCache`). A hit returns the stored result unchanged, so `retrievedAt` stays the time of the real call. Failures are not cached.
- **Timeout and retry:** one `HTTP_TIMEOUT_MS` budget (default 20 s) per lookup. A network error or 5xx (e.g. Overpass 504) is retried once after 0.5 s within that budget; a timeout is not retried.
- **429:** not retried. The provider is not called again for its `Retry-After` (60 s without one, at most 10 min); lookups in that window fail at once with "… rate limited us; not called for N s".
- **Status:** every outcome is recorded as the provider's last call, so a failure, a 429 or a skipped call during back-off shows `DEGRADED`. Nothing is substituted: failed discovery returns no places (503 if every source failed), failed weather returns `available: false` with the reason.
- **Usage policy:** Overpass and Open-Meteo requests carry `User-Agent: ShadeLoop/0.1 (open-source outdoor companion)`; coordinates are rounded before any call; OSM attribution is stored and shown with each place.
- **Planning** fetches weather at the same time as discovery, so a slow Overpass no longer delays weather.
- Limitation: cache and back-off are per process. With several instances each keeps its own.

## MongoDB (Atlas in production)
- **Role:** operational source of truth.
- **Env:** `MONGODB_URI`, `MONGODB_DB`.
- **Verify:** `/health/dependencies` → `mongodb: VERIFIED` (live `ping`).
- **Failure:** `/health/dependencies` returns 503; API calls fail with 500. There is no fallback store.
- **Evidence:** all tests run against mongodb-memory-server (MongoDB binary). The production Docker image was also run against a `mongo:8` container (`mongodb: VERIFIED`). Atlas was verified live on 2026-10-11.

## Gemma 4 on Google AI Studio (production AI)
- **Role:** request parsing, mission proposals and note parsing into proposed observations (all advisory). It does not write report summaries: those are the authoritative template, and no model is called on the completion path. Every proposal goes through the constraint engine (`validateCandidate`); see [AI_POLICY.md](AI_POLICY.md).
- **Code:** `server/src/ai.ts` (the `openai` provider, `aiJson`, `stripThought`).
- **Env:** `AI_PROVIDER=openai`, `OPENAI_BASE_URL` (AI Studio's OpenAI-compatible endpoint, `https://generativelanguage.googleapis.com/v1beta/openai`), `OPENAI_MODEL=gemma-4-26b-a4b-it`, `OPENAI_API_KEY` (AI Studio key), `AI_TIMEOUT_MS`, `AI_MAX_RETRIES`. `render.yaml` sets all but the key.
- **Quirk:** Gemma 4 replies in JSON mode start with a `<thought>…</thought>` block. `stripThought` removes it before `JSON.parse`.
- **Verify:** health calls `GET {base}/models` with the key (at most once per 60 s); `lastCall` shows the latest generation outcome.
- **Failure:** timeouts, HTTP errors and invalid JSON are retried `AI_MAX_RETRIES` times, then templates and keyword parsers take over (`fallbackUsed: true` with a reason).
- **Privacy:** the request prompt, remembered requests (if Backboard memory is on), place names, evidence labels, a weather summary and typed or dictated notes are sent to Google. Coordinates are not.
- **Evidence:** VERIFIED live on 2026-10-11.

## Ollama + Gemma (local AI)
- **Role:** same as above, with a local model.
- **Code:** `server/src/ai.ts` (the `ollama` provider).
- **Env:** `AI_PROVIDER=ollama`, `OLLAMA_URL`, `OLLAMA_MODEL` (default `gemma3:4b`).
- **Verify:** health makes a live `GET /api/tags` (at most once per 60 s; repeated health calls reuse the result) and checks the model is installed. `lastCall` shows the latest generation outcome.
- **Failure:** templates and keyword parsers take over; `fallbackUsed: true` with a reason.
- **Evidence:** VERIFIED locally on 2026-10-11 with `gemma3:4b` (Q4_K_M). Live runs: request parsing succeeded; one proposal was rejected by the engine (34 min > 25 min budget) and templates were used; a later proposal was accepted after duration shortening; a report summary was generated by gemma3:4b through the UI. Two weaknesses showed up in those runs. Summaries claimed observations "aligned with the plan" or were "busier than anticipated" when there was no prior expectation. Step text said "10 minutes" after the engine shortened the step to 6. Both are now addressed: summaries are template-only, and candidates whose text states a duration are rejected (mocked tests only; not re-run live).

Any other OpenAI-compatible chat-completions API works through the same `openai` provider; only AI Studio has been tried.

## Sentry (agent tracing)
- **Role:** traces each plan as an agent run, plus Express 5xx errors.
- **Code:** `server/src/instrument.ts` (init, preloaded with `node --import` by `npm start` and `npm run dev`), `server/src/integrations.ts` (`span`, `tool`), `server/src/ai.ts`, `server/src/missions.ts`, `server/src/app.ts` (`setupExpressErrorHandler`).
- **Spans:** `invoke_agent plan_missions` wraps planning. Inside it, `execute_tool` spans for `get_weather`, `discover_places`, `recall_memory` and `save_memory`, and one `invoke_agent <task>` per AI task (`parse_request`, `propose_missions`, `parse_note`) with a `chat <model>` span per attempt carrying `gen_ai.usage.input_tokens` / `output_tokens`. Agent spans record attempts and whether a fallback was used.
- **Env:** `SENTRY_DSN`. Traces are sampled at 100%.
- **Failure:** without a DSN the SDK isn't initialised and every span is a no-op. Health shows `CONFIGURED` when the SDK is initialised; it can't confirm delivery.
- **Privacy:** span attributes carry names, counts and model names only, never prompts, notes or coordinates. `sendDefaultPii` is off.
- **Evidence:** VERIFIED live on 2026-10-11.

## ElevenLabs (read steps aloud)
- **Role:** natural voice for "read step aloud" in Field Mode.
- **Code:** `speak` in `server/src/providers.ts`; `GET /api/v1/missions/:id/steps/:n/speech` in `server/src/app.ts`; `api.speech` and `readAloud` in `web/src/api.ts` and `web/src/Field.tsx`.
- **Env:** `ELEVENLABS_API_KEY`, `ELEVENLABS_VOICE_ID` (has a default). Model `eleven_flash_v2_5`, MP3 output.
- **Limits:** the endpoint only speaks a step of the caller's own mission, never arbitrary text, and uses the planning rate limit. Audio is cached per process like place results (10 min, 500 entries) and the browser may keep it for a day (`cache-control: private`).
- **Failure:** no key → 404 `NOT_CONFIGURED`; a failed call → 503. Either way, and whenever the device is offline, the client uses the browser's `speechSynthesis` voice.
- **Privacy:** only the step text is sent. Nothing user-written goes to ElevenLabs.
- **Report read-out (added 2026-10-12):** `GET /api/v1/reports/:id/speech` speaks the caller's own report summary (the template text) with the same cache, rate limit and fallbacks. "Listen to report" on the completion screen says whether ElevenLabs or the browser voice spoke.
- **Evidence:** VERIFIED live on 2026-10-11 (steps).

## Tiger Data (TimescaleDB)
- **Role:** a time-series mirror of place-linked observations, read back as "Reports here by time of day (last 90 days, unverified)" on a mission's place. MongoDB stays the source of truth.
- **Code:** `server/src/tiger.ts`; mirrored from `addObservation` in `server/src/missions.ts`; `GET /api/v1/locations/:id/hourly?tz=` in `server/src/app.ts`; `PlaceHours` in `web/src/App.tsx`.
- **Schema:** `shadeloop.observations` hypertable (`time, id, owner_hash, location_id, attribute, value`) and a `shadeloop.conditions_15m` continuous aggregate (15-minute buckets, refreshed every 15 min over the last 90 days). Created on first use. 15-minute buckets keep local hours exact in time zones offset by :30 or :45. The endpoint groups buckets by local hour in the browser's time zone.
- **Env:** `TIGER_DATABASE_URL` (`postgres://…`; TLS is forced with `sslmode=require`).
- **Failure:** a failed mirror write is logged and recorded as `DEGRADED`; the observation is still saved. The hourly endpoint returns `available: false` with a reason and the panel stays hidden. Observations made before Tiger was configured are not backfilled.
- **Privacy and deletion:** no coordinates, notes or tokens. Owners are stored as a SHA-256 hash of the owner id. `DELETE /me` deletes that owner's rows (`tigerRowsDeleted` in the response; `null` if Tiger is off or failed), and the aggregate, which holds counts only, drops them at its next refresh.
- **pgvector similarity (added 2026-10-12):** `shadeloop.place_fingerprints (location_id, name, reports, embedding vector(19))`. The fingerprint is deterministic, with no embedding model: per attribute, the share of the last 90 days' reports for each value. It is refreshed on every mirrored observation and after `DELETE /me`. `GET /api/v1/locations/:id/similar` returns the 3 nearest places with at least 2 reports by cosine distance (`<=>`), shown as "Places with similar field reports". Without the `vector` extension it returns `available: false` and the time-series features keep working. Covered by unit tests of the fingerprint and the not-configured path; **verified live on Render on 2026-10-12** (two test places with 3 reports each matched each other; data deleted afterwards).
- **Evidence:** VERIFIED live on 2026-10-11 (hypertable and aggregate).

## Backboard (opt-in request memory)
- **Role:** remembers a person's own earlier planning requests so new plans respect needs they stated before (for example "no stairs").
- **Code:** `recall`, `remember`, `forgetMemory` in `server/src/providers.ts`; used in `planMissions` (`server/src/missions.ts`); deleted in `deleteData` (`server/src/account.ts`); toggle in `web/src/Settings.tsx`.
- **Opt-in:** off by default. Settings → Memory → "Remember my requests" (`privacy.rememberRequests`). Only when it is on, a key is set and the plan has a prompt: up to 3 related past requests are recalled before planning, and the new prompt is saved after it. One Backboard assistant per owner, created on first save. The plan response reports `planning.memory {provider, recalled, saved}`.
- **Use:** only the AI proposal step sees the remembered requests. The prompt tells the model to respect stated needs in steps and wording but never claim a place meets them; the engine and evidence model don't use memory at all.
- **Env:** `BACKBOARD_API_KEY`.
- **Failure:** recall returns nothing and save returns `false`; planning continues unchanged.
- **Privacy and deletion:** prompt text goes to Backboard only for people who opted in. `DELETE /me` deletes the assistant and its memories (`backboardMemoryDeleted`). Turning the setting off stops recall and saving but does not delete what is stored; `GET /me/export` does not include it.
- **Evidence:** VERIFIED live on 2026-10-11.

## OpenStreetMap Overpass
- **Failover (2026-10-12):** when the main instance fails, `OVERPASS_FALLBACK_URLS` mirrors are tried in order with up to 10 s each; the first error is reported if all fail. At the time of writing, a check from outside Render found the main instance timing out (504) and both default mirrors returning 500, so failover can't help while they're all down. SerpApi covers place search then, and Settings shows OpenStreetMap as amber "covered by SerpApi".
- **Role:** discover parks, gardens, nature reserves and benches near a coarse point.
- **Env:** `OVERPASS_URL`, `HTTP_TIMEOUT_MS` (no key).
- **Failure:** discovery returns 503 if all sources fail; planning continues without named places and says so. Results are cached (see above); a 504 is retried once.
- **Evidence:** VERIFIED live (Bengaluru, 1 km radius, returned 45–60 elements). The public server was also observed returning 504 and taking 10 s+, which is why the timeout is 20 s. On 2026-10-11 it returned 504 for 3 of 4 planning requests. The status then showed `DEGRADED`, and the Discover screen said the place search failed.
- **Attribution:** "© OpenStreetMap contributors (ODbL)" is stored and shown with each place.

## SerpApi
- **Role:** optional extra place results (Google Maps engine).
- **Code:** `server/src/providers.ts` (discovery runs it next to Overpass when a key is set).
- **Env:** `SERPAPI_KEY`.
- **Failure:** like Overpass: its source is marked failed and the other results are still used.
- **Status:** VERIFIED live on Render on 2026-10-12 (returned 20 places for a Bengaluru plan while Overpass failed).

## Open-Meteo
- **Rate limits:** on Render's shared outbound IP, Open-Meteo sometimes answers 429. Weather is already cached per ~1 km cell for 10 minutes and the provider is left alone for its `Retry-After`. Missions then say weather is unavailable and ask you to check conditions, and Settings shows this as amber rather than red.
- **Role:** current temperature, apparent temperature, precipitation, wind and weather code, plus heat/cold/rain safety notes.
- **Env:** `OPEN_METEO_URL` (no key).
- **Failure:** `weather.available: false` with a reason; the mission tells the user to check conditions themselves.
- **Evidence:** VERIFIED live (e.g. 29.8 °C / feels 30.3 °C, retrieved with timestamp).

## Render (hosting)
- **Role:** runs the production Docker image (API plus PWA) at https://shadeloop.onrender.com. Service `srv-db5r54m7bikc73dpa4rg`, free plan, Singapore, auto-deploy from `main`.
- **Code:** `render.yaml` (`runtime: docker`, health check `/api/v1/health`, env vars; secrets are `sync: false` and set in the dashboard), `Dockerfile`.
- **Failure:** the free plan sleeps when idle, so the first request after a quiet spell waits for a cold start (up to about a minute).
- **Evidence:** live on 2026-10-11. `/health/dependencies` there showed `mongodb` and `ai:openai` (Gemma 4) `VERIFIED`; Sentry, Tiger Data, Backboard, ElevenLabs and SerpApi were `CONFIGURED` (keys set, no call made yet on Render). `TRUST_PROXY=1` (one proxy hop) is not verified there.

## Fixture discovery
- **Role:** demos without network. `DISCOVERY_MODE=fixture` returns 3 places named "Sample … (fixture)", with `isFixture: true`, no coordinates, and the attribution "Not a real place". The UI badges them.
- **Status:** DISABLED unless explicitly enabled.

## Browser Web Speech API
- **Role:** optional dictation for notes (SpeechRecognition) and the offline or fallback voice for "read step aloud" (speechSynthesis). Both are behind preferences and labelled.
- **Status:** implemented client-side, not checked by the server, and not covered by automated tests.
